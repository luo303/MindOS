# 长期记忆首版：显式偏好

长期偏好独立于会话热层、摘要和冷层。首版仅支持回复语言、回答详略、代码示例语言；不做隐式提炼、向量检索、历史回填或 AI 写工具。

- 记忆页手动创建、修改、归档和恢复直接生效。每个账号每个键只有一个当前值；更新要求提供版本号，事务内追加快照。
- 用户主动要求记住时，消息落库事务只追加 `memory.extract`（仅 ID）。消费者使用本轮模型一次提炼；不能确定是无条件的长期偏好就返回空。候选不影响回答流，不会自动生效。
- 聊天只展示当前会话的候选，记忆页展示待确认列表。来源、建议值与编辑后保存均可见。确认时比对基础版本，冲突返回 409；旧候选可忽略，不覆盖新决定。
- 账号隔离覆盖记录、历史、候选和消息来源。删除会话会移除候选；生效记录仍保留其结构化值，且注明来源消息已删除。
- 已生效的少量偏好作为结构化默认值传给 Lore。当前用户指令优先；归档、旧版本和候选不进入新一轮的偏好块。旧聊天原文不会因此被改写。

## 接口和运行

所有接口挂在需登录的 `/api/v1` 下。迁移为 `0024_long_term_memory`，先从 `backend/` 执行 `go run ./cmd/migrate up`，再重启后端。提议需要 RabbitMQ 和该轮所选模型；手动设置及已保存偏好读取不依赖 RabbitMQ。

| 接口 | 参数或结果 |
|---|---|
| `GET /memories` | 当前值，包含归档项 |
| `POST /memories` | `key`、`value`；已存在的键返回 409 |
| `PATCH /memories/:id` | `expected_version` 加 `value` 或 `status`；状态可为 `active` / `archived` |
| `GET /memories/:id/versions` | 最近 50 版；使用 `before_version` 查更早版本 |
| `GET /memory-candidates` | 待确认项，可按 `conversation_id` 过滤 |
| `POST /memory-candidates/:id/decision` | `decision: accept/reject`；保存时可附编辑过的 `value` |

首版只解析以「记住／请记住／帮我记住」或英文 `remember` 起头的短句，以及一条明确、无额外限定的偏好。按会话显示的候选由独立查询拉取，不新增 SSE 事件；消费者每进程只提炼一项，单次调用上限 20 秒，忙或调用失败由现有队列退避处理。

## 实现与验收

1. 新建迁移与 `internal/memory`：校验、当前值、版本、候选和认证路由。验证旧版本冲突、并发确认、重复消费和跨账号隔离。
2. 接入对话读取与异步提炼：测试候选只来自明确用户表达，注入只包含已生效项；独立测试提炼和 SSE，不让后者等待前者。
3. 替换现有记忆页占位并接聊天建议卡：测试确认、编辑、拒绝和故障状态。真实部署中使用 PostgreSQL、RabbitMQ 及已配置模型验证完整闭环。
